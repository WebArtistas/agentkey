Approvals

Review requests and manage access in one place.

Access applies to all local clients on your OS account, not a verified agent. AgentKey must be running and unlocked.

How durations work

One attempt is consumed even on failure. Timed and until-revoked access permits repeated actions, which may have repeated side effects. Until revoked survives restarts, but the vault must be unlocked.

New request cards inherit this selection; existing card choices stay unchanged. Saved API and database approvals use this selector. This preference applies to this window until restart. Commands always require a fresh one-attempt approval; this selector does not apply to them.

06 / CONNECT

Connect an agent

Standard MCP — trusted local clients

Use this stdio MCP configuration in a compatible client. Client config formats vary; this is the common mcpServers format. 

{{ connection() }}
  1. Add this server to your agent’s MCP configuration and restart its connection.
  2. Ask it to list AgentKey operations and request access by name.
  3. Review the exact destination and approve in this app.
  4. Let it repeat the operation within the approved duration. Revoke access whenever needed.

AgentKey is a credential broker, not an agent manager. Run and isolate your agents yourself; Docker and a special agent runner are not required. This MCP connection is not OS isolation. No credentials belong in client configuration, chat or prompts. The packaged adapter includes its runtime. Only source builds need a supported Node.js on PATH. Closing the window leaves AgentKey running in the tray.

Bundled usage skill: skills/agentkey/SKILL.md. No browser autofill, arbitrary shell execution, cloud sync or iOS support in this release.
